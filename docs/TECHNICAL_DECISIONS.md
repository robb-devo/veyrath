# Technical decisions

Each decision gives its context, the alternatives considered and the consequences. A decision
marked **pending validation** is final on paper but has not yet been confirmed in the running
game. If it fails validation, record that here before changing course.

## TD-001 — Minecraft Java Edition 26.3

**Status:** Accepted, pending validation · 2026-11-02

**Decision.** Target Minecraft Java 26.3 "Wilderness Bound" (released 2026-09-15, Java 25).

**Why.** It is the newest stable release, and every required component has a stable 26.3 build:

- Fabric Loader 0.19.5
- Sodium mc26.3-0.9.2
- Iris 1.11.7
- Distant Horizons 3.3.4-26.3
- C2ME and Lithium

Since 26.1 the game is shipped unobfuscated. That removes the mappings layer from the build, and
code and stack traces use Mojang's own names. Older versions (1.21.x, 1.20.1) have larger mod
catalogues, but VEYRATH replaces world generation and later gameplay itself, so it gains little
from them. Those versions also miss the 26.x rendering and world-generation changes. Snapshots
(26.4) are excluded because the directive forbids them as a foundation, and because Iris had no
26.4 build when this was written.

**Consequences.**
- Java 25 is required for the build and the game.
- 26.3 changed world-generation data formats: surface rules became material rules, and Feature
  merged with FeatureConfiguration. VEYRATH generates terrain in code, so this mostly affects
  later vegetation features.
- Mojang is preparing a Vulkan renderer. Re-evaluate when moving past 26.3. See
  [research/MINECRAFT_VERSION_COMPARISON.md](research/MINECRAFT_VERSION_COMPARISON.md).

## TD-002 — Fabric as the modloader

**Status:** Accepted, pending validation · 2026-11-02

**Decision.** Fabric (Loader 0.19.5, Loom 1.17, Gradle 9.6.0, Fabric API).

**Why.**
- Fabric is the only loader where the whole selected stack is native: Sodium, Iris, Distant
  Horizons, Lithium, FerriteCore, C2ME and Mod Menu. The main C2ME build is Fabric-only.
- Fabric supported 26.3 on release day.
- NeoForge is a credible second choice; Sodium, Iris and DH all ship for it.
- Forge is ruled out: Iris does not support it, and Distant Horizons 3.3.4-26.3 has no Forge build.
- Quilt adds nothing VEYRATH needs.

See [research/MODLOADER_COMPARISON.md](research/MODLOADER_COMPARISON.md).

**Consequences.** The world engine has no Minecraft or loader dependency (TD-003), so a
NeoForge adapter remains possible later without touching generation code.

## TD-003 — Own world engine behind a custom ChunkGenerator

**Status:** Accepted · 2026-11-02

**Decision.** World generation lives in a pure-Java module, `engine`, with no Minecraft imports.
The Fabric mod is a thin adapter that registers a `ChunkGenerator` and `BiomeSource` and writes
the engine's chunk data into Minecraft chunks.

**Alternatives.**
1. Data-driven noise settings (density functions, noise router). These cannot express a designed
   continent, drainage-following rivers, erosion or a realm-scale rift.
2. Extending terrain mods such as Terralith or Tectonic. They produce vanilla-like geography
   with nicer noise and are tied to the vanilla pipeline.
3. Integrating a larger generator. That would not be our own work and would not fit the art
   direction.

**Why.** The directive asks for designed geography: coherent regions, hydrology, landmarks and
extreme verticality. That needs global knowledge (a realm atlas) which the vanilla per-chunk
noise model does not have. An engine outside Minecraft can be tested, benchmarked and
previewed without starting the game, which made Session 1 productive despite having no access
to Minecraft.

**Consequences.**
- Vanilla structures, carvers and features do not run automatically.
- Vegetation, caves and later structures are generated by VEYRATH systems (Chapter 01 plan).
- Mod compatibility with other world-generation mods is out of scope.

## TD-004 — Rendering stack: Sodium + Iris, Complementary Unbound by default

**Status:** Accepted, pending validation · 2026-11-02

**Decision.** Sodium mc26.3-0.9.2 and Iris 1.11.7 are the rendering base. Complementary Unbound
is the default shader pack, with Photon and Bliss installed for comparison. VEYRATH does not
override vanilla core shaders; Mojang calls that unsupported.

**Why.** Iris is the only maintained shader loader for 26.3, and OptiFine had no 26.3 build when
this was written. Complementary Unbound targets high-end fantasy lighting and has Distant
Horizons support. The final pick between Unbound, Photon and Bliss is made on in-game results.
See [research/RENDERING_AND_SHADER_STRATEGY.md](research/RENDERING_AND_SHADER_STRATEGY.md).

## TD-005 — Distant Horizons fed by VEYRATH's own LOD data

**Status:** Accepted, pending validation · 2026-11-02

**Decision.** Register an `IDhApiWorldGenerator` that returns `API_DATA_SOURCES`. Distant
Horizons asks VEYRATH for LOD sections, and VEYRATH answers with column data sampled directly
from the engine (`LodSampler`), at any detail level from 1 to 256 blocks per column.

**Alternatives.** Let DH generate distant terrain by running the chunk generator itself. That
works for any generator but generates full chunks for every LOD column, which is far too slow at
the distances VEYRATH wants.

**Why.** The engine can answer "what is at (x, z)" anywhere without generating chunks. LOD terrain
comes from the same functions as full chunks, so heights, materials, biomes and floating islands
match at every distance. An engine test checks this at block detail. Measured cost: about 25–100 ms
per LOD section on one core (see [PERFORMANCE_BENCHMARKS.md](PERFORMANCE_BENCHMARKS.md)).

**Consequences.**
- Distant Horizons stays optional at runtime. The integration class is loaded reflectively only
  when DH is present.
- API facts used (DH API 7.2.0 in DH 3.3.4) were read from DH's source and are recorded in
  [WORLD_GENERATION_DESIGN.md](WORLD_GENERATION_DESIGN.md#distant-horizons-lod).

## TD-006 — World height y −256 to 1023, sea level 64

**Status:** Accepted, pending validation · 2026-11-02

**Decision.** The VEYRATH Overworld dimension type uses `min_y = −256` and `height = 1280`, giving
y −256 to 1023. Sea level is 64.

**Why.**
- Monumental relief needs room. On test seeds 1–3:
  - The highest atlas ground is y943.
  - Vesperfall plateaus reach y510–590.
  - The Great Rift floor descends from about y191 inland to sea level.
  - Floating islands sit 110–480 blocks above the ground beneath them. The Crown of Aether
    sits 360 blocks above it, with a 300-block rock root.
- Vanilla's range (−64 to 319) cannot hold this.
- The dimension-type limits allow it. As of 1.21 these were: `min_y` ≥ −2032, `height` ≤ 4064,
  both multiples of 16, and top ≤ 2031. They are not yet rechecked for 26.3.
- 256 blocks below the old floor leave space for the planned deep cave layer.

**Costs considered.**
- Chunk memory grows with section count. Sections that are only air are cheap, and most of the
  sky above y600 is empty except over mountains and islands.
- Lighting and heightmaps work per section, so cost scales with non-empty sections.
- Save size grows with non-empty sections only.

**To confirm in game:**
- Memory and frame time at the target render distance.
- Lighting correctness on tall cliffs.
- Save size.
- Movement over steep terrain.

If any of these is unacceptable, the fallback is `height = 1024` (y −256 to 767) with a lower
summit ceiling.

## TD-007 — Realms: 32,768-block continent tiles with a 1024² atlas

**Status:** Accepted · 2026-11-02

**Decision.** The world is an infinite grid of realms. Each realm is a 32,768 × 32,768-block tile
holding one continent surrounded by sea. Its macro geography is a 1024 × 1024 atlas (32-block
cells), built once per realm in about 10 s and cached.

**Why.** One continent per realm gives designed geography: the archetype regions, one Great Rift,
one Crown of Aether and one Cinder Throne per continent. Erosion and drainage need a bounded
domain. A sea rim makes realms independent, so neighbouring realms can be built in parallel and
in any order.

**Consequences.**
- Every 32 km the player meets open sea before the next continent.
- The realm around spawn is built when the world is created, and neighbours are built lazily.
  The neighbour build stall is issue 7 in [CHAPTER_STATUS.md](CHAPTER_STATUS.md).

## TD-008 — Stream-power erosion on the atlas

**Status:** Accepted · 2026-11-02

**Decision.** Macro relief comes from an implicit stream-power erosion solve (multi-resolution, 4×,
2× then 1× cells) over the atlas, followed by talus relaxation and lake filling. Fine detail is
added in the terrain sampler.

**Why.** Erosion gives connected valleys, ridges with branching spurs and drainage networks that
rivers can follow, which noise alone does not. Doing it on 32-block cells keeps it to a
one-time cost of about 7 s per realm.

**Alternatives considered, not benchmarked side by side:**
- Domain-warped ridged noise alone. It has no drainage coherence: rivers would have to be cut
  in afterwards and would not follow the valleys.
- Particle-based hydraulic erosion at block scale. A 32 km realm has about 10⁹ columns, which
  puts it far outside a world-creation budget.

A side-by-side benchmark is not planned unless the current approach shows a quality problem
that one of these would solve.

## TD-009 — Engine and world coordinates; spawn at world (0, 0)

**Status:** Accepted · 2026-11-02

**Decision.** World block (0, 0) is placed at the curated spawn of realm (0, 0). The offset is a
multiple of 16, so chunks map one to one. The adapter converts between the two systems, and the
engine works in engine coordinates only.

**Why.** Vanilla's spawn search starts near (0, 0). Moving the world instead of patching spawn
code keeps the adapter small and puts players on dry, gentle land with a view.

## TD-010 — Engine materials, vanilla blocks first, VEYRATH blocks later

**Status:** Accepted · 2026-11-02

**Decision.** The engine emits abstract `Material` values. The adapter's `MaterialPalette` maps
them to block states. Phase A uses vanilla blocks chosen for colour and shader response. Phase B
replaces them with VEYRATH blocks and textures, changing only the palette.

## TD-011 — Dedicated launcher profile through an installer script

**Status:** Accepted, pending validation · 2026-11-02

**Decision.** `tools/install/Install-Veyrath.ps1` creates a separate game directory
(`%APPDATA%\.minecraft-veyrath`) and a "VEYRATH" profile in the official launcher. It installs
the Fabric loader version, downloads the modpack from Modrinth with SHA-512 checks and copies
the VEYRATH jar. It never touches other profiles, worlds or the default game directory. It backs
up `launcher_profiles.json` and restores the backup if anything goes wrong.

**Alternatives.**
- Third-party launchers (Prism, Modrinth App) are excellent but ask the owner to change launcher.
- Manual setup is error-prone.

**Consequences.**
- The Minecraft account sign-in and the first launch stay with the owner.
- The installer does not accept the EULA or log in on anyone's behalf.

## TD-012 — Singleplayer first, server-safe by construction

**Status:** Accepted · 2026-11-02

**Decision.** World generation runs on the logical server, which is the integrated server in
singleplayer. The engine is deterministic and thread-safe, and stores nothing per player.
Nothing in Chapter 01 depends on the client except visuals, so a dedicated server can run the
same world later.

## TD-013 — No redistribution of third-party mods or shaders

**Status:** Accepted · 2026-11-02

**Decision.** The repository contains no third-party jars, shader packs or textures. The installer
downloads them from Modrinth onto the owner's PC for personal use. Licences are recorded in
[DEPENDENCIES.md](DEPENDENCIES.md) and [ASSET_LICENSES.md](ASSET_LICENSES.md). Redistribution, for
example a published modpack, needs a licence review per component first.

## TD-014 — Split between the cloud machine and the owner's PC

**Status:** Accepted · 2026-11-02

**Decision.**
- The engine, preview, tests and benchmarks build and run anywhere with Java 25, including the
  cloud machine (`-Pveyrath.skipMod=true`).
- The mod build, data generation, installer and every in-game test run on the owner's PC.

**Why.** The cloud machine's network policy blocks the Fabric, Mojang and Modrinth servers. The
split keeps most engine work independent of the PC, and keeps the claims in these documents
honest about what was verified where.
